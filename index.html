🧠 A filosofia

O que é “Vibe Coding”?

Você define a vibe (a visão, as especificações e as regras) e uma orquestra de agentes de IA executa as tarefas, mantendo o contexto e aprendendo continuamente. O desenvolvedor deixa de ser codificador e vira arquiteto de sistemas cognitivos.

① GSD

Get Shit Done

Nenhuma linha de código sem uma SPEC.md aprovada. Construir a coisa certa, não apenas construir rápido. Fases com plano, execução e verificação empírica.

② Memória

Persistente

Três arquivos simples (primer.md, .claude-memory.md e tasks/lessons.md) dão à IA estado atual, histórico e autoaprendizado a cada sessão.

③ Orquestração

Workflow colaborativo

Planejar ➔ executar ➔ verificar. Planos em tasks/todo.md, lições em tasks/lessons.md, sub-agentes para o que é complexo.

🛠️ Ecossistema

Ferramentas que se encaixam na filosofia

  • Core open-gsd/gsd-pi Casa atual do GSD: meta-prompting e spec-driven development (Spec-Driven).
  • Contexto upstash/context7 Documentação de código atualizada, injetada direto nos prompts.
  • Memória akitaonrails/ai-memory Memória de longo prazo com handoff entre fornecedores de IA (Rust).
  • RAG HKUDS/LightRAG Framework para construir pipelines de RAG.
  • Skills uphiago/recon-skills Recon e pentest: CORS, XSS, SQLi, SSRF, RCE, WordPress, MCP, cloud.
  • Segurança akitaonrails/ai-jail Sandbox multiplataforma para rodar agentes com restrições firmes.
  • Local Ollama + benchmark Rode modelos no seu PC: check_local_llm.py diz quais cabem, sem baixar nada.
  • Harness Codex CLI Agente da OpenAI no terminal: /init, AGENTS.md, skills e plugins.
  • Harness DeepSeek Harness O dsh: tudo é plugin, Web UI local via npx @deepseek-ai/dsh web.
  • OpenAI Dots + migração de GPTs Agentes always-on (29/09/2026) e o prazo de 11/12/2026 dos GPTs para plugins.
  • Conectores MCP na prática Do conceito ao primeiro servidor, com configs para Claude Code, Codex e Gemini CLI.
  • Plugins Ecossistema de Plugins Os 5 sistemas de plugin comparados e o formato de skill que é portátil.
  • Modelos Fine-tuning local Quando treinar (e quando não): decisão, pipeline Unsloth → GGUF → Ollama.

🚀 Como começar

Quatro passos

  1. Estude a filosofiaLeia os guias de Claude Code e GSD 2 para internalizar os conceitos.
  2. Configure a memóriaSiga o guia de memória persistente e crie a estrutura no seu projeto.
  3. Adote o workflowCiclo Planejar ➔ Executar ➔ Verificar, com planos e lições documentados.
  4. ExperimenteExplore as ferramentas listadas e os guias de pasta (Codex, Ollama, DeepSeek Harness, Dots, MCP, Fine-tuning, Plugins) e veja o que cabe no seu fluxo.
